storage.local from chrome code

How a parent-side Experiment API reads and writes its own extension's browser.storage.local directly, without a round-trip to the background script.

Every signature here was checked against a real Thunderbird release build by unpacking omni.ja. Nothing is quoted from memory or from documentation.

  • modules/ExtensionStorage.sys.mjs
  • modules/ExtensionStorageIDB.sys.mjs
  • modules/IndexedDB.sys.mjs
  • chrome/toolkit/content/extensions/parent/ext-storage.js

The problem

An Experiment API runs on the privileged (parent) side. Its background script owns configuration in browser.storage.local. Reaching that same data from chrome code, without a message round-trip to the background script, means talking to the storage backend directly.

Two backends

storage.local has two backends, and the trap is that most snippets found online only use one.

Legacy ExtensionStorage modules/ExtensionStorage.sys.mjs

A JSON file at browser-extension-data/<id>/storage.js.

Current ExtensionStorageIDB modules/ExtensionStorageIDB.sys.mjs

IndexedDB under a reserved user-context principal. Every extension has been migrated to this for years.

Reading via ExtensionStorage.get(id, keys) alone silently returns nothing for a migrated add-on. The correct entry point is the one the platform's own parent implementation uses: ExtensionStorageIDB.selectBackend({ extension }). It both reports which backend is live and performs the one-time JSON→IDB migration before it resolves.

The core

var { ExtensionStorage } = ChromeUtils.importESModule(
  "resource://gre/modules/ExtensionStorage.sys.mjs");
var { ExtensionStorageIDB } = ChromeUtils.importESModule(
  "resource://gre/modules/ExtensionStorageIDB.sys.mjs");

async function openStore(extension) {
  const { backendEnabled } = await ExtensionStorageIDB.selectBackend({ extension });
  if (!backendEnabled) {
    return null;                                   // still on the JSON file
  }
  return ExtensionStorageIDB.open(
    ExtensionStorageIDB.getStoragePrincipal(extension),
    extension.hasPermission("unlimitedStorage"),    // -> persistent quota
  );
}

// read
const db = await openStore(context.extension);
const data = db
  ? await db.get({ accounts: [] })                 // object arg supplies defaults
  : await ExtensionStorage.get(context.extension.id, { accounts: [] });

// write - note the notifyListeners call
const changes = await db.set({ accounts });
if (changes) {
  ExtensionStorageIDB.notifyListeners(context.extension.id, changes);
}

db exposes get, set, remove, clear, getKeys, getBytesInUse, isEmpty.

Four things that bite

notifyListeners is yours to call.

The IDB backend returns a changes object but fires nothing. Skip that call and the background script's browser.storage.onChanged never sees the write — a silent divergence between the two sides. The JSON backend is the opposite: ExtensionStorage.set notifies internally, so do not double-notify on that path.

The change values passed in are raw rather than StructuredCloneHolder-wrapped. That is fine: ExtensionStorage.deserializeForContext falls back to Cu.cloneInto for anything that is not a holder, so the background receives proper oldValue / newValue.

Do not hand-roll the principal.

getStoragePrincipal(extension) is extension.createPrincipal(extension.baseURI, { userContextId: WEBEXT_STORAGE_USER_CONTEXT_ID }). That reserved user context is precisely what keeps the store unreachable from the extension's own page code. Construct it any other way and you open an empty, different database.

selectBackend must be awaited before the first open.

It is what runs migrateJSONFileData. Open the IDB directly on a not-yet-migrated profile and you read an empty store while the real data still sits in the JSON file. It caches per extension in a WeakMap, so calling it on every access is cheap.

openForPrincipal does not pool connections.

Each open() is a fresh IDBDatabase. Caching one connection for the life of the experiment is worth it for a sync loop — but then it must be closed from onShutdown(), or a connection is left behind on add-on reload.

Getting the extension object

Inside an experiment it is context.extension. From unrelated privileged code:

const extension = WebExtensionPolicy.getByID("addon@example.net").extension;

Scope

This reaches storage.local only. storage.session is a different module (extensionStorageSession) and storage.sync is different again.

Full helper class

A complete drop-in file, wrapping both backends behind one interface.

/*
 * Direct access to an extension's browser.storage.local from privileged code.
 *
 * Usage from any parent-side experiment implementation:
 *
 *   const store = new LocalStorage(context.extension);
 *   const { accounts } = await store.get({ accounts: [] });
 *   await store.set({ accounts });
 *
 * This Source Code Form is subject to the terms of the Mozilla Public
 * License, v. 2.0. If a copy of the MPL was not distributed with this
 * file, You can obtain one at http://mozilla.org/MPL/2.0/.
 */

"use strict";

var { ExtensionStorage } = ChromeUtils.importESModule(
  "resource://gre/modules/ExtensionStorage.sys.mjs",
);
var { ExtensionStorageIDB } = ChromeUtils.importESModule(
  "resource://gre/modules/ExtensionStorageIDB.sys.mjs",
);

class LocalStorage {
  #extension;
  #db = null;

  constructor(extension) {
    this.#extension = extension;
  }

  /**
   * The IndexedDB backend, or null if this extension is still on the JSON file
   * backend. Awaiting selectBackend() also performs the one-time migration of
   * existing JSON data into IndexedDB.
   */
  async #backend() {
    if (this.#db) {
      return this.#db;
    }
    const extension = this.#extension;
    const { backendEnabled } = await ExtensionStorageIDB.selectBackend({
      extension,
    });
    if (!backendEnabled) {
      return null;
    }
    this.#db = await ExtensionStorageIDB.open(
      ExtensionStorageIDB.getStoragePrincipal(extension),
      extension.hasPermission("unlimitedStorage"),
    );
    return this.#db;
  }

  async #call(method, ...args) {
    const db = await this.#backend();
    if (!db) {
      // The JSON file backend notifies storage.onChanged listeners itself.
      return ExtensionStorage[method](this.#extension.id, ...args);
    }
    try {
      const changes = await db[method](...args);
      if (changes) {
        ExtensionStorageIDB.notifyListeners(this.#extension.id, changes);
      }
      return changes;
    } catch (error) {
      throw ExtensionStorageIDB.normalizeStorageError({
        error,
        extensionId: this.#extension.id,
        storageMethod: method,
      });
    }
  }

  /**
   * @param {string|string[]|object|null} [keys] - a key, a list of keys, or an
   *   object whose values are used as defaults for missing keys.
   * @returns {Promise<object>}
   */
  async get(keys = null) {
    const db = await this.#backend();
    return db ? db.get(keys) : ExtensionStorage.get(this.#extension.id, keys);
  }

  async getKeys() {
    const db = await this.#backend();
    return db ? db.getKeys() : ExtensionStorage.getKeys(this.#extension.id);
  }

  async set(items) {
    await this.#call("set", items);
  }

  async remove(keys) {
    await this.#call("remove", keys);
  }

  async clear() {
    await this.#call("clear");
  }

  /** Must be called from the experiment's onShutdown(). */
  close() {
    this.#db?.close();
    this.#db = null;
  }
}
